## Wasser — Stand 2026-10-05, fünf Fehler durch Messung gefunden

1. **AO auf Wasser** (großes Ribbeln). Wasser gilt als `isSolidBlock`, also bekam
   jeder Wasserblock 3 seiner 4 Ecken auf 0.52–0.84 abgedunkelt. Pro Block ein
   dunkles Eckmuster, aneinandergekachelt = 1-Block-Raster über den ganzen See.
   Fix: `const ao = type === BLOCKS.WATER ? [3,3,3,3] : getFaceAO(...)`.
2. **Textur mit 7,5 Wellen pro Block.** `sin((px*0.6 + py*0.4) * 3.14)` legte
   7–8 Wellenbänder in eine 16px-Kachel; die Bänder schlugen sich gegeneinander.
   Fix: 4×4-Checker.
3. **Textur nicht tilebar.** Der erste Ersatz nutzte `(px*5 + py*11) % 7` — Periode 7,
   und `16 % 7 = 2`, also passte der Kachelrand nicht zum Anfang = helle Naht an
   jeder Blockgrenze. Fix: Periode 4 (teilt 16).
4. **Wasserlinie falsch.** `if (y <= h)` setzte bei `h === WATER_LEVEL` Land statt
   Wasser: **73 von 837 Spalten (8,7 %)** waren Sand-Inseln mitten im See.
   Fix: `const waterLine = h === WATER_LEVEL && y === WATER_LEVEL;` — der Strand
   beginnt erst bei `WATER_LEVEL + 1`.
5. **`depthWrite` auf dem transparenten Material.** Default ist `true`, also schrieb
   jedes Wasserquad Tiefe und verdeckte das Wasser dahinter. Fix: `depthWrite: false`.

**Die Weltgenerierung war NICHT die Ursache für die schwebenden Platten.**
Messung zeigte 0 Steinsäulen über der Wasserlinie und 0 harte Seegründe. Erst die
Messung der Oberflächenschicht (`getBlock(x, WATER_LEVEL, z)`) zeigte die 73
Sandstellen. Zwei eigene Testfehler führten vorher zu falschen "80 % schweben":
`z%16` statt `z&15`, und es wurde das höchste statt des tiefsten Wassers gesucht.

Verifikation: 3986 Wasserspalten / 0 feste Blöcke an der Oberfläche (4 Seeds),
0 Browser-Exceptions, Screenshot vom echten See bei Tageslicht.
